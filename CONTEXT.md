# Airflow Provider: Google Sheets

Airflow-провайдер для чтения/записи Google Sheets через Hook/Operator паттерн
Airflow. Контекст один на весь репозиторий.

## Language

**Merge Key**:
Колонка, по значению которой `GoogleSheetsWriteOperator` (`write_mode="merge"`)
сопоставляет входящие строки с уже существующими строками в таблице — для
удаления старых и добавления новых вместо них.
_Avoid_: key column, ключевая колонка (использовать единый термин Merge Key)

**Schema**:
Параметр оператора (`schema: dict[str, dict]`), явно объявленный вызывающим
кодом DAG — описывает тип (`str`/`int`/`float`/`date`/`datetime`/`bool`) и
формат конкретной колонки для конвертации при чтении/записи.
_Avoid_: column schema (когда речь о Schema целиком, не о записи одной колонки)

**Inferred Schema**:
Schema для Merge Key, которую `GoogleSheetsWriteOperator` сам выводит по форме
**входящих** значений текущего запуска, когда вызывающий код не передал Schema
для этой колонки явно (то есть для неё вообще нет записи в `schema`-словаре —
*любая* явная запись, даже формально не про даты, например `{"type": "str"}`,
считается осознанным выбором пользователя и блокирует Inferred Schema).
Используется только для распознавания ISO-дат (`YYYY-MM-DD`); строгий порог —
все непустые входящие значения должны совпадать с шаблоном, иначе Inferred
Schema не применяется и поведение остаётся raw-as-is.
_Avoid_: synthetic schema, auto-detected schema, синтетическая schema

**A1Range**:
Value-тип координат/диапазона в A1-нотации (`utils/a1.py`): парсит обе границы
(`"C3:F10"`, открытые `"C3:F"`), знает sheet-префикс, конвертацию букв⇄индексов
и рендер ячеек/диапазонов. Единственный носитель A1-математики — операторы не
парсят и не собирают A1-строки вручную.
_Avoid_: range string, координаты как пара `(col, row)` россыпью

**Written Extent**:
Value-тип «протяжённость записанной таблицы» — факт, который каждый write-режим
(overwrite/append/merge) конструирует по итогам своей записи: верхняя строка,
наличие физической строки заголовка, `total_rows` (все физические строки
таблицы после операции, ВКЛЮЧАЯ строку заголовка, если она есть), записанная
ширина. Единственный вход серверной сортировки (`sortRange`):
`sort_start`/`sort_end`/`num_columns` — его свойства, width-contract описан
один раз в его docstring.
_Avoid_: тройка skip_header/end_row/num_columns как самостоятельные величины,
пересчитываемые каждым режимом заново; «число строк данных» как поле (даёт
off-by-one при уже существовавшем заголовке — заголовок входит в total_rows)

**Merge Plan**:
Набор операций удаления и добавления строк, посчитанный для одного запуска
merge — до того, как эти операции выполняются против Google Sheets API.
Состоит из операций удаления (диапазоны строк по существующим совпавшим
ключам) и строк на добавление (все входящие строки).
_Avoid_: delete_ops/append_rows как два самостоятельных понятия — это две части
одного Merge Plan

## Relationships

- Каждый merge-запуск имеет ровно один **Merge Key**.
- **Schema** может (но не обязана) включать запись для колонки, которая
  используется как **Merge Key**.
- Когда **Schema** для **Merge Key** не задана явно, оператор пытается
  построить **Inferred Schema** взамен — это не часть **Schema**, переданной
  пользователем, а отдельный, временный (на один запуск) механизм.
- Каждый merge-запуск производит ровно один **Merge Plan**, построенный из
  индекса существующих строк (нормализованного через **Schema** или
  **Inferred Schema**) и входящих строк.
- Нормализация **Merge Key**/**Inferred Schema** (`utils/merge_key.py`) и
  построение **Merge Plan** (`utils/merge_planner.py`) — чистая логика,
  тестируемая независимо от Hook/Operator I/O (без mock_hook).
- **Политика (2026-07-02): «решения записи — чистые функции, I/O —
  оркестровка».** Паттерн Merge Plan — норма для всего нового кода write-пути:
  решение (писать ли заголовки, окно/ширина — **A1Range**, нарезка батчей,
  протяжённость сортировки — **Written Extent**) вычисляется чистой функцией /
  value-типом с прямыми unit-тестами; `_execute_*` только читает, спрашивает и
  исполняет. Старый код переезжает при касании, не массово. Тесты новых
  решений — по значениям или финальной сетке (FakeSheet), не по
  `mock_hook.call_args`. Проработка до плана:
  `docs/plans/20260702-pure-write-planning-design.md`.

## Example dialogue

> **Dev:** "Если для **Merge Key** не передана **Schema**, мы вообще ничего не
> нормализуем?"
> **Domain expert:** "Раньше — да, отсюда и баг с дублями. Теперь, если значения
> **Merge Key** во входящих данных похожи на ISO-дату, мы строим **Inferred
> Schema** и нормализуем через неё — но только для `date`, не для `datetime`."

# sort_keys для GoogleSheetsWriteOperator

## Overview

В merge-режиме новые строки всегда оказываются в хвосте таблицы (append). Нет способа получить таблицу, отсортированную по ключевой колонке — например, новые даты вверху, старые внизу. Аналогичная проблема актуальна для append и overwrite.

Решение: параметр `sort_keys: list[str] | None = None`. Если задан, после завершения любой записи выполняется один `batchUpdate` с `sortRange` — серверная сортировка на стороне Google Sheets, без чтения данных.

## Solution Overview

Новый параметр `sort_keys: list[str] | None = None`, формат элементов: `"col:asc"` / `"col:desc"`.

**Валидация в два этапа:**
- `__init__`: формат (наличие `:`, direction = `asc`/`desc`, непустое имя колонки) — ошибки видны при загрузке DAG
- `execute`: существование колонки в `headers` — ошибки видны при запуске

**Метод `_execute_sort`** вызывается в конце каждого режима и отправляет `sortRange`.
Принимает явный `skip_header: bool` вместо чтения `self.has_headers` — каждый call site передаёт правильное значение в зависимости от того, есть ли физически заголовок в листе:

```python
def _execute_sort(self, hook, headers, sheet_id, table_start_col, table_start_row, skip_header: bool, end_row: int):
    sort_specs = []
    start_col_idx = self._column_letter_to_index(table_start_col)
    for spec in self.sort_keys:
        col, direction = spec.split(":", 1)
        col_idx = start_col_idx + headers.index(col.strip())
        sort_specs.append({
            "dimensionIndex": col_idx,
            "sortOrder": "ASCENDING" if direction.strip().lower() == "asc" else "DESCENDING",
        })
    data_start = (table_start_row - 1) + (1 if skip_header else 0)
    # No-op на пустом диапазоне: Google API отклоняет sortRange, где
    # startRowIndex >= endRowIndex. Покрывает пустые данные / только-header.
    if data_start >= end_row:
        return
    hook.batch_update(self.spreadsheet_id, [{
        "sortRange": {
            "range": {
                "sheetId": sheet_id,
                "startRowIndex": data_start,
                "endRowIndex": end_row,
                "startColumnIndex": start_col_idx,
                "endColumnIndex": start_col_idx + len(headers),
            },
            "sortSpecs": sort_specs,
        }
    }])
```

**Место вызова по режимам** — `skip_header` и `end_row` вычисляются на call site:

**overwrite** — вызов после `trim_sheet`:
```python
skip_header = bool(self.write_headers and headers)
end_row = (start_row_num - 1) + len(all_rows)  # all_rows уже включает header-строку, если write_headers=True
self._execute_sort(hook, headers, sheet_id, start_col, start_row_num, skip_header, end_row)
```

**append** — вызов после последнего батча.

Ограничение: при `sort_keys` append `cell_range` **запрещён** (см. валидацию в `__init__`) — запись и sort range обязаны строиться от одного `table_start`, иначе они разъезжаются. Поэтому в append+sort базовая точка всегда `start_col/start_row` из `table_start`.

Важно: при `sort_keys` (или `write_headers=True`) высоту существующей таблицы нельзя считать по одной первой колонке — Google Sheets обрезает хвостовые пустые строки и не видит внутренних пустот в первой колонке. Читаем существующий диапазон **по всей ширине таблицы** и берём последнюю непустую строку:
```python
end_col = self._index_to_column_letter(
    self._column_letter_to_index(start_col) + len(headers) - 1
)
existing_block = hook.get_values(
    self.spreadsheet_id, f"{prefix}{start_col}{start_row}:{end_col}"
)
# последняя строка, где есть хоть одна непустая ячейка (индекс 1-based от start_row)
existing_row_count = 0
for i, r in enumerate(existing_block):
    if any(str(c).strip() for c in r):
        existing_row_count = i + 1

header_written_this_run = (existing_row_count == 0) and self.write_headers and bool(headers)
# ... запись заголовка если header_written_this_run ...
# ... батчи append ...

if self.sort_keys:
    skip_header = header_written_this_run or (existing_row_count > 0 and self.has_headers)
    end_row = (start_row - 1) + existing_row_count + (1 if header_written_this_run else 0) + len(rows)
    self._execute_sort(hook, headers, sheet_id, start_col, start_row, skip_header, end_row)
```

Существующая проверка «пустой ли лист» для записи заголовка остаётся single-cell при `sort_keys is None` (обратная совместимость с текущим тестом), а full-width чтение выполняется дополнительно только когда нужен `existing_row_count` для sort range.

**merge** — вызов после `repeatCell` (или после блока append если `append_rows` пуст).
Все нужные данные уже есть в методе:
```python
# ВНИМАНИЕ: сейчас total_existing объявлен ВНУТРИ `if append_rows:` (строка 532).
# Sort нужен даже когда append_rows пуст (только deletes), поэтому вынести
#   total_existing = len(existing_keys_raw) + (1 if headers_just_written else 0)
# ВЫШЕ ветки `if append_rows:` (до строки 531), иначе NameError.
rows_after_merge = total_existing - total_deleted + len(append_rows)
end_row = (table_start_row - 1) + rows_after_merge

# skip_header: заголовок в листе если он уже был (existing_keys_raw непустой) или только что записан
skip_header = bool(existing_keys_raw) or headers_just_written
self._execute_sort(hook, headers, sheet_id, table_start_col, table_start_row, skip_header, end_row)
```

## Technical Details

### Формат параметра

```python
sort_keys=["date:desc", "region:asc"]
```

- Регистр направления нечувствителен: `"ASC"`, `"Asc"`, `"asc"` — всё принимается
- Колонки указываются именами **после** `column_mapping` (те, что реально в таблице)
- **Не добавлять** в `template_fields` — раз templating не нужен, всю format-валидацию делаем в `__init__` (ошибки видны при загрузке DAG). Если в будущем понадобится templating — перенести format-валидацию в `execute()` и убрать её из `__init__`.

### Валидация формата в `__init__`

Контракт (единый, без противоречий): **весь формат** проверяется в `__init__`; `execute()` проверяет только то, что зависит от рантайм-данных (существование колонок, наличие headers).

```python
if sort_keys is not None:
    if not isinstance(sort_keys, list):
        raise TypeError(f"sort_keys must be a list, got {type(sort_keys).__name__}")
    if not sort_keys:
        raise ValueError("sort_keys must be a non-empty list or None")
    if write_mode == "overwrite" and clear_mode == "range":
        raise ValueError(
            "sort_keys is not compatible with overwrite + clear_mode='range': "
            "sorting across partial column ranges desyncs neighbouring columns"
        )
    if self.cell_range and write_mode == "append":
        raise ValueError(
            "sort_keys is not compatible with append + cell_range: "
            "write target and sort range must share the same table_start"
        )
    seen_cols = set()
    for spec in sort_keys:
        if not isinstance(spec, str):
            raise TypeError(f"sort_keys item must be a string, got {type(spec).__name__}: {spec!r}")
        if ":" not in spec:
            raise ValueError(f"sort_keys item '{spec}' must be 'column:asc' or 'column:desc'")
        col, direction = spec.split(":", 1)
        col = col.strip()
        if not col:
            raise ValueError(f"sort_keys item '{spec}': column name is empty")
        if direction.strip().lower() not in ("asc", "desc"):
            raise ValueError(
                f"sort_keys item '{spec}': direction must be 'asc' or 'desc', got '{direction.strip()}'"
            )
        if col in seen_cols:
            raise ValueError(f"sort_keys column '{col}' is specified more than once")
        seen_cols.add(col)
```

Примечание: запрет `append + cell_range` использует `write_mode` из локального аргумента (или `self.cell_range` после присваивания) — расположить блок в `__init__` **после** `self.cell_range = cell_range`.

### Валидация колонок и headers в `execute`

Только рантайм-проверки — **после** `_apply_column_mapping(headers)` (строка 269 кода), чтобы `sort_keys` сверялся с именами колонок *после* маппинга. НЕ проверять существование колонок до маппинга:

```python
# ВАЖНО: этот блок идёт после `headers = self._apply_column_mapping(headers)`.
if self.sort_keys:
    if not headers:
        raise ValueError(
            "sort_keys requires named headers (has_headers=True or list[dict] input)"
        )
    for spec in self.sort_keys:
        col = spec.split(":", 1)[0].strip()
        if col not in headers:
            raise ValueError(
                f"sort_keys column '{col}' not found in headers: {headers}"
            )
```

Дубли sort-колонок отсекаются форматной валидацией в `__init__` (`seen_cols`), поэтому `headers.index(col)` в `_execute_sort` безопасен от неоднозначности внутри `sort_keys`. (Дубли в самих `headers` листа — отдельный редкий случай; при необходимости добавить отдельную проверку, но это вне текущего скоупа.)

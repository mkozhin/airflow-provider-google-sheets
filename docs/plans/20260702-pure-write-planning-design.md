## Суть

CONTEXT.md канонизировал паттерн Merge Plan: нормализация Merge Key
(`utils/merge_key.py`) и построение Merge Plan (`utils/merge_planner.py`) —
чистые модули с прямыми unit-тестами, без mock_hook. Остальные *решения*
write-пути вшиты в I/O-процедуры `_execute_*` (operators/write.py), поэтому
проверяются только перехватом вызовов: **139 из 201** тестов write-оператора —
`MagicMock` c assert'ами по `call_args` (тест проверяет механизм, потому что
интерфейс не отдаёт результат решения).

Целевая форма каждого режима — как у merge: **«посчитай план → исполни план»**.
`_execute_*` остаётся тонкой оркестровкой: прочитал → спросил чистую функцию →
исполнил.

## Оставшиеся вырезки (материал будущего плана)

### 1. `decide_header_write` — решение «писать ли заголовки»

Сегодня ТРИ расходящиеся семантики пустоты (это источник minor-находки
plan-review по плану 20260701):

```python
# append, sort-ветка (write.py:640-641): пустота ОКНА (последняя непустая строка)
existing_row_count == 0 and self.write_headers and bool(headers)
# append, легаси (649-652): пустота ОДНОЙ верхней ячейки
if not first_row: ...
# merge (782): пустота колонки merge-ключей
if not existing_keys_raw and self.write_headers and headers: ...
```

Вынести в чистую функцию с ЯВНЫМ параметром пробы:

```python
def decide_header_write(existing, *, write_headers, headers,
                        probe: Literal["cell", "window", "key_column"]) -> bool
```

⚠️ Вырезка ОБНАЖИТ различия семантик. Решение «узаконить параметром vs
унифицировать» — продуктовое (унификация меняет поведение), принять при
проработке плана, не по умолчанию.

### 2. `split_batches` — нарезка на батчи

4 копии цикла `for i in range(0, len(...), batch_size)` + `time.sleep(pause)`
(write.py:569-577, 658-664, 852-857, 945-949). Чистый генератор:

```python
def split_batches(rows, batch_size) -> Iterator[tuple[int, list]]  # (offset, batch)
```

Пауза между батчами остаётся у оркестровки (это I/O-забота).

### 3. Инвентарь прочих кандидатов на вынос (проверить при проработке)

- Резолв target-диапазона (`cell_range or f"{prefix}..."` + `startswith(prefix)`
  guard) — 3 почти идентичных блока (533-536, 618-622, 733) — вероятно,
  поглощается A1Range.
- Вычисление insert-позиции merge (`rows_after_deletion`/`insert_start`,
  839-845) — чистая арифметика внутри I/O-кода.

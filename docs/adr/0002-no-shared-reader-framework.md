# ADR-0002: Общий «читающий каркас» для read.py и UniqueValuesOperator не вводим

Дата: 2026-07-02 · Статус: accepted

## Контекст

Архитектурное ревью 2026-07-02 (кандидат №6): `GoogleSheetsUniqueValuesOperator`
(manage.py:349–416) — почти-дубликат read-пути (`read.py:167–256`: `_build_range`
+ чтение заголовков + чанк-цикл), по сути ReadOperator с редьюсером «уникальные
значения колонки». Рассматривался вынос общего читающего каркаса
(`_build_range`/`_read_chunks` + плагин-агрегатор) на два оператора.

## Решение

**Максимум (каркас) — отклонён. Минимум — принят через A1Range:** дословно
задублированный парсинг `cell_range` (manage.py:353–356 ≡ 366–369, та же логика
в read.py:163) схлопывается при миграции read/manage на `A1Range`
(этап 2 внедрения A1Range; этап 1 — write.py, Task 0 плана
`20260701-idempotent-append-design.md`).

## Причины отклонения каркаса

1. **Один адаптер = гипотетический seam.** У каркаса ровно два потребителя,
   оба стабильны, третьего не предвидится — за интерфейсом ничего не
   варьируется.
2. Абстракция «каркас + плагин-агрегатор» рискует быть сложнее суммы двух
   конкретных копий — модуль станет мельче, а не глубже.
3. Самый раздражающий кусок (двойной парсинг внутри одного класса) устраняется
   минимумом бесплатно.

## Условия пересмотра

Появление **третьего** оператора-читателя (ещё один потребитель чанкового
чтения с заголовками) делает seam реальным — тогда вопрос каркаса открыть
заново.
